# Podketo: live release comparison, 2026-10-27

## Confirmed failure and fix

With an unlocked synthetic Vault containing an apex Credential whose URL is
`https://podketo.pl/pl/signin.html`, click toolbar **Log in** on the live homepage.
The published 0.1.7 upload artifact opens a second homepage and receives `no-form`
twice. The command discards the saved path and constructs `https://{urlDomain}/`.
The same command exists on main after test-only PR #105. This is a navigation
failure, not a missing field detector or an unreleased detector improvement.

The candidate opens the saved same-origin signin URL after `no-form`, fills its
native controls and receives a successful content acknowledgement. It verifies
HTTPS, absence of userinfo and exact browser-bound origin before navigation and
after redirects, then re-reveals under the current session. It never broadens
apex/www matching. `commands.test.ts` reproduced the real homepage `no-form`
result before the change (expected filled, actual no-form) and passes afterward.

## Regression scope and diagnostics

Existing observed homepage/signin DOM coverage remains in the form corpus and
built inline browser suite. Added command tests cover the live failing navigation,
path/query retention, invalid URL/sibling/foreign/HTTP/userinfo/port rejection,
redirect origin changes, lock during navigation and no retry after target change.
Playwright context routing misses the first navigation of extension-created tabs;
that path was therefore verified live separately, not mislabeled as offline CI.
Firefox packaging is checked; no installed Firefox behavior parity is claimed.
The defect is in shared command logic, not the Chromium/Firefox transport.

Minimal diagnosis requires no credential values: **locked** is shown in the
extension UI; **no suggestion** means an unlocked empty menu (check exact host,
Credential type and selected server); **no fill** with an existing suggestion
requires checking occupied controls and the displayed result; **wrong URL** means
there is no login pair on the current page. `www.podketo.pl` redirects to
`podketo.pl`, so a www-only entry is related and requires explicit selection.
`filled` means DOM delivery, `no-form` means no eligible target, and `blocked`
means a gate rejected the operation. None warrants weakening origin or unlock.

Local validation: 217 Vitest files / 3600 tests; typecheck and all three target
builds plus debug Chromium; inline, capture, generator, agent-live, agent-frames,
credential-submission, shared-unlock-platform and shared-unlock-chromium-channel
browser scripts passed. The repository has no separate lint command; docs/icons
checks and diff whitespace checks passed. Audit high/critical gate passed with
two existing moderate Vitest advisories. No dependency changes were made.
